# workflow-car-vitals

Ported from `references/xstate/examples/workflow-car-vitals/main.ts` (serverless workflow "car vitals checks").

- `machine.go`: `NewVitals` (`vitalscheck`: four parallel invoked checks, `always` guard, final `VitalsChecked`), `NewWorkflow` (`checkcarvitals`: `WhenCarIsOn` -> `DoCarVitalChecks` -> `CheckContinueVitalChecks` -> after 1000 -> `DoCarVitalChecks`; `CarTurnedOffEvent` at root with `log`), `Delay`, the real checks (`Printer.RealCheck`, `RealChecks`) and the entry (`Run`, `RunWith`).
- `main.ts` runs a demo actor at import time (about 7.5 s of real timers); the Go `Run(w)` is that entry. `RunWith(w, speedup)` divides every duration (checks, `after`, the entry's sleeps) by `speedup` so tests do not take 7.5 s.

## Not ported
- `package.json`, `pnpm-lock.yaml`, `tsconfig.json`, `.gitignore`: Node/pnpm/vite-node setup (`cockatiel` is listed in `package.json` but not imported by `main.ts`).
- `delay()` rejecting with `{ type: 'ServiceNotAvailable' }`: ported as `Delay` returning `ErrServiceNotAvailable`, but the app always calls it with `errorProbability` 0, so it never rejects in a trace; covered only by the Go-only `TestDelay_ErrorProbability`.
- The cancellation of promise actors: JS promises cannot be cancelled, so the real checks ignore `ctx` and keep printing `Completed ...` after the invoking state is left (visible in the golden stdout after `Car turned off`). `Run` waits for those pending checks before returning, as the Node process waits for pending timers. The trace stubs in `machine_test.go` do honour `ctx`; this is invisible in the snapshots.
- Order of the four `Starting ...` lines: JS runs the synchronous head of each promise body at invoke time, in invoke order. A Go promise body runs on its own goroutine, so `Printer.printStarting` serialises the lines in invoke order (`machine.go:185`). Without it the order is nondeterministic (observed: `Starting checkTirePressure, checkCoolantLevel, checkBattery, checkOilPressure`). This is a harness detail of the entry, not a machine change.
- `console.log('Done with vitals check', event.output)`: written to the `io.Writer` of `NewWorkflow`; the output printed is `undefined` (see below), rendered by `formatOutput`. `log('Car turned off')` goes through the actor logger (`xs.WithLogger`), set to the same writer in `RunWith`.
- The `complete` subscriber (`workflow completed ...`) is ported but never fires: the root machine has no final state.
- `output: ({ context }) => context` on the final state `VitalsChecked`: not a machine output (it sits on a state node, not on the machine config), so the done event carries `undefined`; the Go port declares it the same way (`machine.go:113`) and the golden confirms the engine matches (`vitals.golden.json` last step `output: null`, stdout `Done with vitals check undefined`).

## Trace coverage
- `testdata/workflow-car-vitals.golden.json` (`scripts/trace/workflow-car-vitals/workflow-car-vitals.ts`, `useClock`): the checks of the vitals sub-workflow are replaced by real-timer stubs (coolant 20 ms, tire 40, battery 60, oil 80, values 90/32/12/45) through `workflow.implementations.actors.vitalscheck.provide(...)`, the same stubs on the Go side. Covers `CarTurnedOffEvent` and an unknown event in `WhenCarIsOn`; `CarTurnedOnEvent` -> `DoCarVitalChecks` (child `0.checkcarvitals.DoCarVitalChecks`); `CarTurnedOnEvent` ignored in `DoCarVitalChecks`; vitals done -> `onDone` -> `CheckContinueVitalChecks`; `after 1000` not yet elapsed (999) then elapsed (+1) -> `DoCarVitalChecks` with a fresh child; `CarTurnedOffEvent` during the checks (child stopped, stale promise results ignored); and while waiting in `CheckContinueVitalChecks` (the `after` timer is cancelled: +1000 stays in `WhenCarIsOn`). Every state and transition of the workflow.
- `testdata/vitals.golden.json` (`vitals.ts`): the `vitalscheck` machine alone (not exported by `main.ts`, taken from `workflow.implementations`), checks at 100/200/300/400 ms. Initial context all `null` with four children; after each check completes the `always` guard is false (contexts fill one by one), after the last one it is true -> `VitalsChecked` (status `done`, no children). Both sides of the guard and all four `onDone` assigns.
- `testdata/workflow-car-vitals.stdout.txt` (`workflow-car-vitals.stdout.ts`): the real `main.ts` with real timers; three check rounds, the last cut off by `Car turned off` while tire/battery/oil are still pending.
- `TestStdout` runs the unchanged `RunWith` entry inside `testing/synctest` so CPU load cannot reorder timers with different deadlines. Its test writer adds 1 ns of virtual console latency at each `Done with vitals check` line. This places the third-round tire completion strictly after car-off, matching the recording's accumulated timer lateness; without it both have the same virtual deadline. The test compares the complete output byte-for-byte with the unchanged fixture.
