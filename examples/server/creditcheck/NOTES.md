# mongodb-credit-check-api

Ported from `references/xstate/examples/mongodb-credit-check-api/`.

- `machine.go`: `machine.ts` (`creditCheckMachine`: Entering Information, Verifying Credentials, a parallel CheckingCreditScores of three bureau regions, DeterminingInterestRateOptions). Same ids, state keys, invoke ids, guards, actions and `console.log` lines. The context is `CreditProfile` (`model.go`, JSON keys = JS context keys).
- `services.go`: `services/machineLogicService.ts` as a `Services` struct of functions (`NewServices` builds the real ones over a `Store`; tests inject stubs) and the `Env` (sleep, random) behind the bureau and rate simulations.
- `store.go`, `mongo.go`: the `Store` interface (machineStates, creditReports, creditProfiles), an in-memory fake (`MemoryStore`, used by the tests) and the real adapter on `go.mongodb.org/mongo-driver/v2` (`ConnectMongo`).
- `server.go`: `index.ts` + `services/actorService.ts` as `net/http` handlers (`POST /workflows`, `POST /workflows/{id}`, `GET /workflows/{id}`, `GET /`), `getDurableActor` as `Server.durableActor`, and `Run` (the `app.listen` message).
- `cmd/server/main.go`: the program; set `MONGODB_URI` (JS: the `<your mongo uri here>` placeholder in `actorService.ts`), it listens on :4242.

## Not ported
- `README.md`, `package.json`, `pnpm-lock.yaml`, `tsconfig.json`, `.prettierrc`, `.gitignore`: docs and Node/pnpm/ts-node setup.
- `express`, `body-parser`: replaced by `net/http`. Express-specific behaviour not reproduced: the `Cannot GET /x` 404 page (Go's mux answers `404 page not found`), `X-Powered-By`/`ETag` headers, body-parser's error pages.
- `zod`: `userCredentialSchema` is re-implemented by hand (`verifyCredentials` in `services.go`: strings of 1..255 for the names, exactly 9 for SSN, lengths in UTF-16 units). zod's own error text (a JSON list of every issue) is not reproduced; the Go error names the first invalid field (`Invalid Credentials. Details: invalid SSN`).
- `machine.ts` `@xstate-layout` comment and the `types` block: editor layout data and TypeScript types.
- Events without a string `type` on `POST /workflows/:id`: in JS this reaches `actor.send` with a bad event; Go answers `400 Bad Request` (also for malformed JSON). Covered by `TestBadEvents`, not by a golden trace.
- After a 500 on `POST /workflows/:id` the JS handler also calls `res.status(200).send(...)`, which Express rejects (headers already sent). Go returns after the 500. The JS fake router keeps the first response, so the golden shows the 500 (`GET`/`POST` on an unknown id).
- Per-request actors: like JS, every request builds a new actor and leaves it running so in-flight bureau calls finish and persist. `Server.Close` stops them; a long-running server accumulates them exactly as the JS one does.
- `creditReports` / `creditProfiles`: `actorService.ts` only assigns `collections.machineStates`, so in JS `collections.creditReports` and `collections.creditProfiles` stay `undefined` and `checkReportsTable`, `saveCreditReport` and `saveCreditProfile` are silent no-ops (the existing-report branch can never fire for a real run). The Go `MongoStore` wires all three collections; the golden traces use stub services, so they are unaffected. Behaviour change versus JS: with a real database a second workflow for the same SSN finds the stored reports.
- Persist and save errors: JS throws inside the async subscription handler (an unhandled rejection). Go logs them through `Server.Logf` / `Services.Log` and keeps going.
- `saveReport` stores `context.EquiGavinScore` for every bureau (machine.ts passes `creditScore: context.EquiGavinScore` regardless of `params.bureauName`); kept as is.
- The MongoDB adapter (`mongo.go`, `cmd/server`) is compiled but cannot be exercised without a database: only `plainValue` (BSON to JSON-shaped values) has a unit test (`mongo_internal_test.go`). BSON stores `undefined` as `null`; the server strips nil entries from the persisted snapshot before storing (`plainJSON`), so no `null` appears in stored documents.
- `_id`: MongoDB adds an ObjectId to documents and `GET /workflows/:id` returns it in JS; the Go `MachineState` has no `_id` field, so the document is returned without it (random value, not recordable).
- The real bureau and rate services sleep 1 to 10 s with `Math.random`; `Env` makes sleep and random injectable. `TestCheckBureauUsesRandomForSleepThenScore` checks the `range({min, max})` arithmetic and the call order against `Math.floor(0.5*(10000-1000)+1000) = 5500` computed in bun.

## Trace coverage
The seven machine traces use a simulated clock in both runtimes. `scripts/trace/mongodb-credit-check-api/lib/record.ts` provides callback actors to the original JS machine; `traceMachine` in `stubs_test.go` provides matching actors to the Go machine. Each callback runs the existing SSN-keyed service result and sends the invocation's done or error event. Explicit `advance` steps reach service boundaries: credentials 20 ms, reports 40, bureaus 100/200/300, middle score 40, rate 60. All 71 snapshots and all sent events are unchanged from the earlier real-time recordings.

The original waits sampled between independent service timers. A scheduler pause could skip an intermediate state: the score-error trace sampled at nominal 380 ms, only 20 ms before rejection. `TestTraceObserverPause` advances to that stage, pauses the observer for 80 ms, and verifies that rejection occurs only after the next virtual advance. Service validation and middle-score calculation still call the real Go functions. Logs and HTTP server traces retain promise actors and real service timers; their fixtures are unchanged.
- `testdata/happy.golden.json` (`happy.ts`): Submit, a second Submit ignored while verifying, CheckingForExistingReport with the guard false in all three regions, all FetchingReport, EquiGavin and GavUnion FetchingComplete one after the other, allSucceeded true, DeterminingMiddleScore, FetchingRates, RatesProvided, then Submit and an unknown event ignored in the final state.
- `testdata/invalid-credentials.golden.json`: Verifying Credentials `onError` for a short SSN, an empty firstName and a non-string lastName, each back to Entering Information with the ErrorMessage.
- `testdata/bureau-failure.golden.json`: EquiGavin and GavUnion bureau calls reject (FetchingFailed, allSucceeded false, "Failed to retrieve credit scores."), then a retry where the Gavperian existing-report guard is true (score from the stored report overrides the context) and the other two fetch.
- `testdata/existing-reports.golden.json`: Gavperian bureau call rejects; the retry hits the existing-report guard for EquiGavin and GavUnion (stored 690 and 710 replace the context 720 and 580) and fetches Gavperian.
- `testdata/reports-table-error.golden.json`: `checkReportsTable` rejects in all three regions (FetchingFailed from CheckingForExistingReport), allSucceeded false.
- `testdata/rate-error.golden.json`, `testdata/score-error.golden.json`: `generateInterestRates` / `determineMiddleScore` reject; neither state has `onError`, so the machine ends in status `error` (children stay listed, as in JS).
- Guard and transition coverage: each `*ReportFound` guard is true once (EquiGavin and GavUnion in existing-reports, Gavperian in bureau-failure) and false in the other runs; `allSucceeded` is true (happy, existing-reports, bureau-failure retry) and false (bureau-failure, existing-reports and reports-table-error first runs); `checkReportsTable` `onError` in all three regions (reports-table-error); `checkBureau` `onError` for EquiGavin and GavUnion (bureau-failure) and Gavperian (existing-reports); every `onDone`, the `Submit` transition and `Verifying Credentials` `onError`/`onDone` are taken. `DeterminingMiddleScore` and `FetchingRates` have no `onError` (rate-error, score-error show that). The machine has no `after` delays.
- `testdata/logs.stdout.txt` (`logs.stdout.ts`, `TestLogs`): the `console.log` lines of the happy run: `saving report to the database...` x3, `allSucceeded guard called`, `saving results to the database...`, `emailing user ...:  [ 5 ]`, `emailing sales team ...  Gavin Bauman [ 5 ] 650`.
- `testdata/server.golden.json` (`server.ts`, `TestServerTrace`): the real `index.ts`, `actorService.ts` and `machine.ts` behind a fake router and an in-memory `mongodb` (`lib/load-server.ts`, because express, body-parser and mongodb are not installed), stub services, fixed `Math.random` ids. Covers `GET /`, `POST /workflows` twice, invalid then valid Submit with a GET after every wait (every persisted state of the happy path, with the invoked children), an ignored event, `GET`/`POST` on an unknown id (404, 500), a second independent workflow.
- Go-only tests: `TestVerifyCredentials` (zod rules), `TestDetermineMiddleScoreSortsAsStrings`, `TestGenerateInterestRate`, `TestCheckBureauUsesRandomForSleepThenScore`, `TestDefaultSleepStopsWithContext`, `TestReportsAndProfilesRoundTripThroughStore`, `TestStartFailsWhenStoreFindFails`, `TestPersistFailureIsLoggedNotReturned`, `TestBadEvents`, `TestRun`, `TestPersistedStateRestoresIntoMachine`, `TestPlainValue`.

## Resolved library finding
`TestServerTrace` exposed uppercase JSON fields and an unresolved zero output in persisted `PromiseSnapshot` values. The library now writes lowercase fields and includes output only for completed promises, preserving completed zero values. The strict server golden passes. See `docs/porting/notes/examples-lib-findings.md` for the original finding.
