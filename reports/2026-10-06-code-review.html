1. MoveDirectory can delete its own source through a symlink alias

examples/workflow/mediascanner/files.go:177

The overwrite checks compare lexical absolute paths. If alias points to real, MoveDirectory(alias/movie, real/movie) passes both checks even though the paths name the same directory. RemoveAll deletes the source; the subsequent Rename fails. The ancestor variant deletes the containing tree too.

Observed: Independent reproduction: source exists=false after the call; Rename returns ENOENT. The separate ancestor regression also fails with movie.mp4 missing.

Suggested fix: Check physical identity and resolved parent ancestry before any destructive overwrite. Preserve the intended behavior of moving a leaf symlink. Add alias-to-same-directory and alias-to-ancestor regression cases.

2. Cross-system SendTo races with the receiving actor and loses events

xstate/system.go:216

relay calls the destination core.send directly while holding the source system lock. Separate root actors have separate locks, so a concurrent receiver.Send or snapshot read is not protected. The mailbox and snapshot can be modified concurrently even with immutable integer context.

Observed: Independent go run -race reproduction: 22 data races; count=997 after 1,000 sends. Exact counts depend on scheduling. The test uses only public actor APIs.

Suggested fix: Deliver foreign-system messages through synchronization owned by the destination. Define cross-system dispatch and ordering explicitly: taking the target lock while retaining the source lock can deadlock reciprocal sends. Cover direct sends, delayed sends, snapshot reads, and reciprocal messaging.

3. Stopping the stopwatch can deadlock with a pending tick

examples/stopwatch/machine.go:36

Callback cleanup runs under the actor system lock and waits on done. The ticker goroutine can be blocked acquiring that same lock in SendBack, so it cannot exit and close done. Stop, reset, and actor shutdown can hang indefinitely.

Observed: TestReviewStopWhileTickIsPending times out after one second. Its stack shows cleanup waiting at machine.go:39 and the ticker waiting in callback_actor.go:66. A 100 ms observer delay arranges the pending tick.

Suggested fix: Stop the ticker and signal cancellation without joining the goroutine under the actor lock. SendBack already ignores delivery after callback disposal. Retain a regression that arranges a pending tick during cleanup.

4. An unfinished POST body blocks all workflow API operations

examples/server/workflow/server.go:92

send takes the server-wide mutex before decoding the HTTP request body. A client can open a workflow and then leave its event body unfinished, holding the lock needed by workflow reads, creates, and other sends. The example server has no read deadline. The index page does not require this lock.

Observed: TestReviewSlowBodyDoesNotBlockOtherWorkflows gates the body reader: GET stays blocked until the POST body is released.

Suggested fix: Decode and validate a bounded request body before locking. Keep the read/restore/send/persist sequence atomic, and release the lock before network response writes. Configure HTTP read deadlines for the runnable server.

6. Pointer contexts retain stale child actors after in-memory restoration

xstate/persist.go:172

With a context of type *struct{Child ActorRef}, persistValue and reviveValue do not traverse the pointer. Direct GetPersistedSnapshot → WithSnapshot restoration creates new children, but the context still references the old child. After stopping the original parent, sends through the restored context go to the stopped actor.

Observed: TestReviewPointerContextRestore: staleRef=true; an INC sent through the restored context leaves the restored child count at 0 instead of 1. The runtime logs a send to the stopped child.

Suggested fix: Traverse pointer-backed context values during persistence and revival, copying values before replacing actor markers. Handle nil pointers and cycles deliberately. Verify that context references resolve to the restored Children entries without mutating the original context.

7. The global candidate cache permanently retains dynamically created machines

xstate/machine_logic.go:21

machineCaches is a package-level sync.Map keyed by the machine pointer, with no removal path. Once an event lookup populates it, the machine, state nodes, context, and implementation closures remain strongly reachable after actors stop and caller references disappear. Repeated CreateMachine or Provide use accumulates retained machines.

Observed: TestReviewMachineCacheRetention creates and stops 100 machines, drops local references, and forces two garbage collections. All 100 remain in the global cache.

Suggested fix: Own the cache on StateMachine so its lifetime follows the machine. Do not clear a shared machine cache on one actor's Stop. Add a lifetime regression; fixed, long-lived machine definitions are less exposed than per-request machine creation.

8. Atom equality conflates closures with different captured values

store/shallowequal.go:85

sameValue compares functions by reflect.Value.Pointer(), which identifies executable code rather than the closure environment. Different closures from one factory can compare equal. Atom.Set then keeps the previous function and suppresses notification.

Observed: TestReviewCompanionClosureUpdate creates a closure returning 1, sets one returning 2, and still reads 1. The factory is marked noinline to make the shared-code case stable.

Suggested fix: Handle functions separately. Treat non-nil functions conservatively as unequal unless callers provide a comparator; keep nil equality. Apply this to function fields and selected values that share the same equality helper.

9. SCXML turns explicit JavaScript null into undefined

scxml/ecmascript.go:112

Exporting a JavaScript null yields Go nil. toJS maps every nil back to undefined, so an explicit <data expr="null"> changes meaning before the next guard or action. Nested context and event values use the same conversion path.

Observed: TestReviewCompanionNullDatamodel declares x=null and sends GO with guard x === null. The actor remains in state a instead of entering b.

Suggested fix: Preserve null and undefined as distinct values throughout recursive export/import. Use an explicit undefined representation for unbound data and preserve null in context, arrays, and event payloads.

The ordinary JSON-config importer case was excluded because the porting manifest scopes that helper to revived machine definitions. A graph failure requiring a nondeterministic initializer was also excluded as an inherited behavior. Documented runtime constraints were not reported as standalone bugs; the stopwatch finding is an example violating those constraints.

Fix guidance preserves shared-machine lifetimes and warns against introducing reciprocal cross-system lock deadlocks. FromStore is described as returning an error snapshot because actor initialization catches its type assertion panic.
